> **读者**：排期决策者 + 实施者。**与其它文档的关系**：[`000-工程规划.md`](000-工程规划.md) §8（规划期能力矩阵）、

## 1. 背景与现状（为什么现在可以 Go）

PTY 在 Android 版上长期是 ❌，根因在 `安卓环境能力清单` §F 第 4 级已拆透，且**技术面已全部验证**：

| 事实 | 状态 | 证据 |
|---|---|---|
| `/dev/ptmx` 应用域可 open（SELinux 放行，dsh 口径） | ✅ 真机 M2105K81C | R1：`pi-web.pty-selftest.json` `ptmx-open=true` |
| `forkpty→unlockpt→setsid→TIOCSCTTY→exec sh` 全链（node-pty 原生件） | ✅ 3/3, 528ms | `evidence/pty-route-a-release.logcat.txt`、`pi-web.ptynode-selftest.json` |
| 原生件 `libpty_node.so` 交叉编译成功（node-pty@1.1.0，NDK） | ✅ build 41027607245 | `pty.lock.json`（aosp-node-pty 仓） |
| node-pty 的 N-API addon 可被进程内打包 dlopen + 种子 require cache | ✅ 路线 A 加载器实跑 | `pi-web-launch.js#runPtyNodeSelftest` route-2 |
| 纯 JS 方案走不通（O6） | ✅ 结论 | §F 第 4 级 O6 ③ |
| 引擎换装 Maven AAR 双包机制 | ✅ 已在生产 | `runtime.lock.json` + `verify-runtime.mjs` |

**结论**：PTY 的产品化不再是「能不能」，而是「接通并验证」。缺的只是四件事的**落地**：
① 原生件随包进 nativeLibraryDir；② `require("node-pty")` 运行时可达；③ 能力标志翻转为 supported；
④ 终端面板 + 一条试运行 bash 工具通路联调。

## 3. 目标与范围

### 3.1 V1 目标（本方案交付）

| 目标 | 判据 |
|---|---|
| T1. 终端面板可用 | 打开终端 Tab → 交互式 mksh shell 可输入/回显/退格；`tty` 返回 `/dev/pts/N`；颜色/光标（xterm-256color）；resize 生效；Ctrl-C(SIGINT) 中断；`exit` 关闭面板 |
| T2. `/api/terminal` 能力翻转 | `GET /api/terminal` 返回 `{supported:true, platform:"android", …}`；POST 创建 → SSE 事件流 → write/resize/kill 全链 |
| T3. 最简 PTY bash 工具（试运行） | 单次 spawn mksh `-c`，靠 **PTY exit 事件**取退出码返回（区别于 android-exec 哨兵）；120s 超时；workspace cwd；围栏同现制 |
| T4. 原生件随包 + 运行时可达 | `libpty_node.so` 在 `nativeLibraryDir`；`require("node-pty")` 命中（启动期常驻加载器） |
| T5. 真机取证 | 主流的 T1–T4 在 M2105K81C/Android 11 真机逐项留证 |

### 3.2 明确不在 V1（→ 第二轮）

- **bash 工具深化**：常驻 PTY shell 复用、流式输出、进程组 kill 对齐、`exit N` 语义、与 android-exec 的哨兵路径治理合并。
- 终端多开/会话恢复的额外优化（upstream 已带 terminal-tab-state，直接复用）。
- x86_64 模拟器上的 Next 引导（berberis SIGSEGV，**L-ENV**，非本工程任务）。
- `MANAGE_EXTERNAL_STORAGE` 等合规红线（不变）。

## 4. 架构总览

```
┌─ 系统 WebView（Chrome 94，真机）───────────────────────────┐
│  TerminalPanel.tsx（xterm.js）                              │
│   ├─ POST /api/terminal      （创建，{cwd,cols,rows}）        │
│   ├─ GET  /api/terminal      （能力查询 supported?）          │
│   ├─ EventSource …/events    （output/exit 下行）             │
│   └─ POST …/[id]             （{type:input|resize|…} + DELETE）│
└─────────────────────────────┬──────────────────────────────┘
                 HTTP loopback（随机端口，免密；已有 105-auth）
┌─ 进程内 Node（node-runtime:26.13.0）───────────────────────┐
│  app/api/terminal/*route.ts                                  │
│   └─ lib/terminal-manager.ts  require("node-pty")            │
│        └─（启动期常驻加载器已把 exports 种子进 require cache）  │
│  android-pty 扩展：/pty-test（保留诊断） + 最简 bash 工具      │
└─────────────────────────────┬──────────────────────────────┘
                     N-API（dlopen / Node 符号由引擎解析）
┌─ nativeLibraryDir（APK 解压只读，G3 合规执行位）──────────────┐
│  libnode.so（runtime AAR）                                   │
│  libpty_node.so（node-pty AAR，DT_NEEDED libnode.so）         │
│  libc++_shared.so（runtime AAR 唯一提供）                     │
└─────────────────────────────┬──────────────────────────────┘
                     forkpty/openpty → /dev/ptmx
┌─ 终端 shell ───────────────────────────────────────────────┐
│  /system/bin/sh（mksh）+ 真 PTY（/dev/pts/N，TIOCSCTTY）→ 交互  │
└─────────────────────────────────────────────────────────────┘
```

- **无前端 fork**：TerminalPanel 与 /api/terminal 全部是 upstream `pi-web v0.12.1` 原样。
- **无自研 PTY 实现**：节点用官方 `node-pty`（微软 + 社区），原生件来自 `aosp-node-pty` AAR。
- **能力门**：`terminal-capability.ts` 前置门保证「supported 才允许创建」，且真装载才 supported（宪法 A6）。

## 5. 关键技术改动

### 5.1 依赖与引擎升级（决策 D2）

对齐现有 `node-runtime` 的 Maven 方案，新增 `node-pty`：

| 位置 | 改动 |
|---|---|
| `gradle/libs.versions.toml` | `nodeRuntime = "26.13.0"`；新增 `nodePty = "26.13.0"`；新增 `node-pty = { module = "io.github.fellow99:node-pty", version.ref = "nodePty" }` |
| `app/build.gradle.kts` | 依赖区新增 `runtimeOnly(libs.node.pty)`（与 `libs.node.runtime` 并列） |
| `runtime.lock.json`（工程根） | `active.node : 24.22.1 → 26.13.0`；补 `libnodeSha256=bc5d15f8…`、`libcxxSharedSha256=b5d97c38…`、`libpty_nodeSha256=7f514ee5…`；新增 `active.pty.maven` 坐标；上游指向 `aosp-node-runtime` 的 26.13.0 条目 |
| **新增** `verify-pty.mjs`（lock 来源镜像）；随锁文件 `pty.lock.json`（工程根镜像 aosp-node-pty） | 镜像 `verify-runtime.mjs`：断言 `node-pty-26.13.0.aar` 内 `jni/arm64-v8a/libpty_node.so` 的 **SHA-256 = lock** + ELF 门禁（ET_DYN · 无 PT_INTERP · AArch64 · **DT_NEEDED 含 libnode.so** · 16KB 对齐） |
| `scripts/devtest.mjs` G1 | 引擎锁校验口径升级到 26.13.0（含 pty 锁） |
| **退役** `scripts/provision-pty.mjs` | `libpty_node.so` 现由 Maven AAR 直进 nativeLibraryDir，不再投放 jniLibs（保留 `--check` 语义并入 `verify-pty.mjs`） |
| `scripts/provision-engine.mjs` | 保留为 26.13.0 本地零网兜底（--check 验 sha 改 26.13.0）或退役；二选一，倾向保留零网兜底 |

> **关键纪律**：`verify-pty.mjs` 必须在构建门禁里跑（像 `verify-runtime.mjs`），否则 AAR 版本漂移静默带进 APK。
> pty 只带 `libpty_node.so`，**绝不**带 `libnode.so`/`libc++_shared.so`（runtime AAR 唯一提供，避免 double clutter）。

### 5.2 node-pty 运行时可达（决策 D3）

**前端/依赖面**：改 `scripts/crop-rules.mjs` 的 `node-pty` 规则 —— 由「裁剪 `node_modules/node-pty/**` 全量」改为
「裁剪 `node_modules/node-pty/prebuilds/**`（其他平台预编译件，本就一个都加载不了）」，**保留 `lib/` JS 与
`build/Release/` 存根**。`serverExternalPackages` 已含 `node-pty` ⇒ Next 把它当 external，运行时
`lib/terminal-manager.ts#require("node-pty")` 解析到载荷内 `node_modules/node-pty`。

**原生件加载（启动期常驻）**：把 `pi-web-launch.js#runPtyNodeSelftest` 的 **route-2**（nativeLibraryDir
dlopen + 种子 require cache）从「仅 `PI_ANDROID_SELFTEST=1`」**提升为启动恒执行**，且在 pi-web server boot 之前：
1. 读 `PI_ANDROID_NATIVE_LIB_DIR`（Kotlin 已注入）；
2. `process.dlopen` 载 `libpty_node.so`（实体路径 or soname 回落，沿用已验证逻辑）；
3. 把装载后的 exports `Module` 写进**全局** `require.cache`，键 = `require.resolve("node-pty")` 解析出的
   `node_modules/node-pty/build/Release/pty.node` 绝对路径（或 node-pty 的 `loadNative` 实际查找路径）；
4. 失败则**结构化如实上报**（宪法 A6）：`terminal-capability` supported=false + `boot-facts` 记 `pty.ready=false`，
   **绝不静默降级**成假终端。

> 实现提示：node-pty 的 `utils.loadNative` 在 `build/Release/pty.node` 与 `prebuilds` 两个候选；因为 prebuilds 已裁、
> 我们把 `libpty_node.so` dlopen 后种子进 cache 按 `pty.node` 解析绝对路径，`require("node-pty")` 即命中。
> 种子点要覆盖 pi-web server 的模块解析域（用工程根 `require.cache`，不是局部 `createRequire` 域）。

### 5.3 能力翻转（patch 0001）

改 `patches/v0.12.1/0001-terminal-capability-unsupported.patch` 触及的 `lib/terminal-capability.ts`：

- 把 `"android"` 从 `PTY_LESS_PLATFORMS = ["openharmony","harmonyos","android"]` 中**移除**（只留 openharmony/harmonyos）。
- 但在 `terminalCapability()` 的 supported 判定里**不只看平台名单**，再加一条运行时实测：`<nativeLibraryDir>/libpty_node.so`
  存在（可 dlopen 判定），使「**真装载才 supported**」。做法：伪装常量平台名单退出后，走 `ptyEvidence()` 增补
  「libpty_node.so 在位/可装载」事实，任一不成立仍返 supported:false + 结构化 reason。
- 结果：Android 上 `GET /api/terminal` 返 `{ok:true,supported:true,platform:"android",…}`；POST 不再 501。
- **保持逆可逆**（patch 纪律）：该 patch 仍幂等可反向，`--check` 门禁。

> 保持「supported 是运行时探测结论，不是编译期常量」的原则 —— 这样假如某设备 SELinux 收紧、或 AAR 缺失，
> UI 得到的是「不支持」而非「作为故障的 500」，与上游 200+标志位同形。

### 5.4 终端 shell 选择

- `terminal-manager.ts` 默认 `SHELL || /bin/sh`；Android 无 `$SHELL` ⇒ `/system/bin/sh`（mksh R59，已在位，O5 实测）。
- mksh 接受 `-l`（登录 shell），与 `terminal-manager` 的 `args=["-l"]` 兼容（真机验证 T1 确认）。
- env 由 `shellEnvironment()` 注入 `TERM=xterm-256color`、`COLORTERM=truecolor`、`LANG=C.UTF-8`（无需改）。
- 终端 cwd 走 `/api/terminal` POST 的 `cwd`（受 `getAllowedFileRoots` 围栏 + 工作区根约束，已有 patch 0002/0005 语境）。

### 5.5 最简 PTY bash 工具（决策 D1 / V1 试运行）

**目标**：证明「PTY 承载工具」路径（拿到真实 `exit` 事件 → 退出码），作为第二轮 bash 深化的探路。

- 新增一个单次 spawn 的最小实现（建议放 `payload/extensions/android-pty/` 内，命名如 `ptyBash` 工具，或作为
  覆盖 `bash` 的同名扩展的一支开关）。为避免动已可靠 android-exec，**V1 以独立最简实现试运行**，不进
  android-exec 主体。
- 语义（对齐 upstream `bash` + 本工程纪律）：
  - 每次调用 spawn 一条 `mksh -c '<command>'` 到 **真 PTY**（`pty.spawn('/system/bin/sh',['-c',cmd],{cols,rows,cwd,env})`），
    非常驻（V1 最小）；
  - **完成判据：PTY 的 `onExit` 事件**（node-pty 原生线程 waitpid，能拿到真退出码 —— 这是哨兵法拿不到的核心收益）；
    加 120s 超时兜底 + 进程组 kill（沿用 `android-exec.js` 的 `detached+kill(-pid)` 纪律）；
  - stdout 即 PTY 输出（含 mksh 提示/颜色，模型侧可选处理），stderr 合并（`2>&1`）；
  - cwd = 会话目录（不存在直接失败）；围栏同现制；内存输出有界（防刷屏，如截 64KiB）。
- 注册为 pi 扩展命令/工具，进 `settings.json` 默认工具集试运行（或显式加开关，排期自定）。

> 第二轮再做的：常驻 PTY shell 复用（省 fork）、流式 `onData` 增量回传、`exit N`/`exec`/TSTP 语义、
> SIGINT 透传、与 android-exec 哨兵路径的治理合并、把其它工具名（find/grep 等不走 PTY）分层归档。

### 8.1 门禁（构建期，无设备）

|---|---|---|
| G1 锁 | `verify-runtime.mjs` + `verify-pty.mjs` | 26.13.0 AAR 内 3 个 .so 的 sha + ELF 门禁与 lock 逐字一致 |

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 26.13.0 AAR 实际 ICU 与锁不符（no-icu） | Next 载荷编译期崩 | 锁 `builtFrom.configure=small-icu` 已核；Phase A 后跑 boot-facts Intl 探针复验；verify-runtime sha 锁 |
| node-pty JS 恢复后载荷体积增（prebuilds 已裁，JS ~几十 KB） | 可忽略 | crop 只裁 prebuilds，体积增量计入 assemble 报告 |
| 常驻加载器 cache 种子域与 Next external require 域不一致 | `require("node-pty")` 仍 miss | 用工程根 require.cache + 按 `loadNative` 实际查找路径作 key；Phase B 用 `/pty-test` 真链路验证 |
| mksh `-l` 交互兼容 | 终端怪现象 | T1a/prompt 验证；必要时在 shellEnvironment/patch 里微调 |
| 引擎 24.22.1→26.13.0 回归（pnpm/git/桥） | 其余工具回退 | Plan B 跑 regression 四件套 + C1/C2 自检（26.13.0 下复跑） |
| 某设备 SELinux 收紧拒绝 dlopen libpty | 该设备 supported:false | 能力翻转保留「真装载才 supported」，如实降级（宪法 A6） |
| PTY 工具 exit 事件在极端场景仍不达 | 工具挂 | 保留 120s 超时 + 进程组 kill 兜底；最简工具只是试运行 |
