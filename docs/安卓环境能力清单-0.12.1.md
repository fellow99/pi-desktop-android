## 0. 判据与方法

1. **基准集合（三源）**：① ark as-built 的 **33 项主表**（其沿用 hos 能力清单 v0.12.1 §A.2 口径，编号 1–33 与 ark 逐条对齐）；② ark README/001 中**清单外**的壳功能（会话导出、技能包、选择器 Tab、局域网访问、窗口状态记忆、品牌化）；③ **Android 特有增量**（git / pnpm / 前台服务 / 翻译层执行环境）。
2. **判定方式**：以本工程源码/产物/本轮探针与 E2E 记录为 as-built 证据（[`docs/002-真机验证记录.md`](002-真机验证记录.md) + `docs/evidence/*`）；**本机未实测的一律 ⬜**，不按"上游同款应该一样"写成 ✅。与本表强相关的两个本机事实：
   - **引擎**：`io.github.fellow99:node-runtime:24.2.0`(Maven) 为 `--with-intl=none`（Intl 全缺，O2 ⚠️）⇒ 已换装上游 **aosp-node-runtime v24.22.1（small-icu）**（[provision-engine.mjs](../scripts/provision-engine.mjs)，sha256 锁定）；第二轮端上 boot-facts 实测：Intl 8 构造器 + 属性转义编译全 ✅、WASM validateOk ✅；
   - **执行环境**：本轮仅有 x86_64 模拟器（**berberis arm64→x86_64 翻译层**）。Next.js 的 require 图在该层确定性 SIGSEGV（四象限穷尽：引擎×JIT/jitless×内存，见 §E）⇒ **一切"pi-web 服务起来之后"的用例无法在模拟器取证**，统一记 ⬜（真机交接命令见 [`docs/002`](002-真机验证记录.md) E2E 节）。第二轮新增**不依赖 pi-web 就绪的取证通道**：宿主能力自检（`am start --ez selftest true` → `pi-web.selftest.json`）、落盘事实（boot-facts/engine-facts）、`runtime.keepAlive` 真启停 + dumpsys、受控崩溃哨兵——本轮判据全部走这些通道。

## A. 结构性差异（逐项判定的成因）

| 维度 | `pi-desktop-ark`（HarmonyOS） | `pi-desktop-android`（本工程） | 后果 |
|---|---|---|---|
| 引擎 ICU | ohpm node-runtime 24.2.0（**ICU 完整**，属性转义可用） | Maven 24.2.0 为 **no-icu**（O2 事故根因）⇒ 已换 **24.22.1-small-icu**（投放制，不入库） | Android 必须用投放制引擎；vendor 兼容步骤保留为 no-icu 保险（small-icu 下为等价替换） |
| 宿主桥 | 文件信箱（2ms 往返） | **JNI 直调 + Kotlin Handler**（库主路）| 更低延迟；`ping`/`echo` 全链已实测 ✅ |
| 引擎投放 | ohpm 中心仓包 | Maven 只出 bridge；**引擎由 `scripts/provision-engine.mjs` 投放 jniLibs**（lock sha256 门禁） | 换引擎 = 换 lock 口径，无需发版 |
| 载荷形态 | `resfile/pi-web/pi-web.tar.gz`（resfile 即文件） | `assets/pi-web/pi-web.tar.gz` ⇒ **AGP 去壳改名 `.tar` 存裸档**（已适配：Kotlin 按魔数双形态） | 第二轮裁剪后 **30,413 文件/307.4MiB**，优于 ark 375MB 档 ✅（12 条新规则，devtest G2/G3 守门） |
| 裁剪基线 | tar.gz ≈130MB 级 | tar.gz **74.5MiB**（bsdtar 自检通过；原 128.2MB） | 优于 ark 档 |
| 执行环境 | **真机原生 arm64**（2in1/tablet/phone 已验） | 本轮仅 **模拟器 + berberis 翻译层** | Next require 图在翻译层 SEGV（§E）——ark 无此问题 |
| JIT 形态 | **编译期固定 compat（--jitless）**，code-mode 随之禁用 | **默认 JIT**（24.22.1；翻译层探针 O1 实测 wasm=ok/likely-jit） | Android 无 OHOS 的 W^X ACL 门；code-mode 理论可用 ⬜ |
| 服务 | 进程内 Next，127.0.0.1 免密 | 同（同一份 launch 脚本移植） | 口径一致 |
| 补丁 | 6 条（PTY-1/CWD×2/export/picker×2 之 ArkTS 语境） | **6 条 Android 化**（0001 加 android 平台、0002 改 PI_ANDROID_ROOTS、0003 adb 别名、0004/0005/0006 移植） | 全部幂等可反向，`--check` 门禁 |
| 包体 | HAP 46MB + 载荷 130MB | **APK（debug）实测 181MB**（引擎 81.5MB + 载荷 74.5MiB + 库/代码；裁剪前 420MB） | 裁剪已落地 ✅（release 包需按新载荷重出） |
| 存储模型 | OHOS 沙箱 + 逐目录 user_grant 授权 | **app-specific 外存免权限真实路径**（主线）+ SAF 桥（**Phase 2 已接**：takePersistableUriPermission，content:// 异步契约） | ark 的 L1 授权门问题在 Android 主线上**不存在** |
| **真机 WebView 内核** | ark 随系统 webview 内核较新 | 真机出厂系统 WebView 锁 **Chrome 94**（设备唯一实现、不可切换），而 pi-web 构建目标 chrome 111 | 需壳层注入 ES2022 垫片，见 §A.1 |

### A.1 真机 WebView（Chrome 94）旧内核兼容（2026-10-30 实测修复）

**背景**：真机 `M2105K81C`（Android 11, SDK30）系统 WebView = `com.google.android.webview 94.0.4606.85`，全设备仅此一个、无 beta/canary 可切。pi-web v0.12.1 构建目标 chrome 111，少量 ES2022 API 与动态视口单位**未被 Next 转译**，在旧内核上运行即崩/失效。

**修复（两层垫片，均只在 API 缺失时补、绝不覆盖新内核行为）**：

| 现象 | 根因（Chrome 版本门槛） | 修复 |
|---|---|---|
| 回答完成后整页跳 **This page couldn't load**（Next global-error） | `Array.prototype.findLastIndex/findLast`（Chrome 97+）在 React 渲染期抛 TypeError，未被错误边界捕获（`lib/message-display.ts`、`codemode-view.ts`） | `assets/webview/polyfill-webview.js` 垫片 |
| 红条 **模型错误 e?.throwIfAborted is not a function**、选择器 No models | `AbortSignal.prototype.throwIfAborted`（Chrome 103+，客户端 page chunk fetch 后调用）**＋ 服务端同 API**（pi-ai 1.2.0 需 Node 25+，引擎为 24.22.1） | 客户端垫片 **＋** `payload/pi-web-launch.js` Node 侧垫片 |
| 打开工作区终端报 **AbortSignal.timeout is not a function** | `AbortSignal.timeout` 静态方法（Chrome 103+；终端通道 `fetch(...,{signal:AbortSignal.timeout(15000)})`） | 客户端垫片（返回到时以 TimeoutError 自动 abort 的 signal） |
| 页面/侧栏内容**不充满**（侧栏底工具栏不贴 WebView 底） | 动态视口单位 `100dvh`（Chrome 108+）在旧内核被整条丢弃致高度塌陷（`html,body{height:100dvh}` 及 `--app-viewport-height` 回退） | polyfill 特性检测后注入 px `!important` 覆盖样式，按 innerHeight 同步 + resize/旋转重算；硬编码 dvh 弹窗换算为 % |
| 点图片上传按钮**无反应** | pi-web 用隐藏 `<input type=file accept=image/* multiple>`，WebView 默认不处理文件选择 | `WebChromeClient.onShowFileChooser` → 系统 SAF 文档/相册选择器（无需存储权限）；`onActivityResult` 回传单/多选 uri，取消即收尾；真机选图已在输入框出缩略图 ✅ |
| 同类隐患 | `structuredClone`（Chrome 98+，多个 UI chunk） | 垫片（支持 Date/Map/Set/ArrayBuffer/TypedArray/循环检测，非法类型抛 DataCloneError） |

**注入时机/可诊断性**：`MainActivity` 在 `WebViewClient.onPageStarted`（早于页面任何脚本）经 `evaluateJavascript` 注入 IIFE；`onPageFinished` 复查全部垫片是否在位、缺则补注并 log。新增 `WebChromeClient.onConsoleMessage` 把页面 console/未捕获 JS 异常转发到 logcat（tag `pi-web-console`；此前 WebView 客户端异常完全静默，是本轮定位关键）。WebView 远程调试（chrome://inspect）经 `WebView.setWebContentsDebuggingEnabled(BuildConfig.DEBUG)` **仅 debug 开**（G11 诊断面纪律；为此启用 buildConfig feature）。
